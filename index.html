ARROWFALL

A VR archery roguelite for Meta Quest that runs on the web. Skate on momentum with arm gestures, draw and release a real bow in mid-air, throw black holes into the horde. Solo or two-player online co-op.

TypeScriptVitethree.jsWebXRWebRTCCloudflare WorkersVitest
My role

Product owner, game designer, director.

I built ARROWFALL with Claude (Anthropic's AI) as my coding partner. I set the design, made the look and quality calls, playtested on the headset, and ran the whole Meta store submission: the in-app purchase, the privacy policy for Meta's Data Use Checkup and the store listing.

Directing an AI collaborator to ship a complete product, and checking that what it builds is actually right, is the skill this project shows.

What shipped
  • Submitted to the Meta Horizon Store on Oct 18, 2026 (in review): free download, Full Game as an in-app purchase, packaged as a Trusted Web Activity APK
  • 48 stacking items, 16 monster types plus elites, 3 mini-bosses and a final boss, THE ECLIPSE
  • 14 arena looks, each with its own procedural synthwave score
  • DUO: online co-op with Quick Join matchmaking, proximity voice chat, revives and player reporting
  • Meta-progression with unlockable cosmetics; works offline after the first launch
  • Website at arrowfall.lol with landing page, changelog and privacy policy

Under the hood

Determinism

Every run replays bit for bit

The simulation is pure TypeScript: step(world, input), one seeded RNG, no three.js, DOM or clock inside, enforced by tests. Runs are recorded as inputs, so the gameplay video and stills were rendered at 1440p60 from a real headset run, even in a different visual look.

Performance

90 Hz on a mobile chip

Instanced crowds, LOD for distant monsters and the floor mirror, a patched three.js for multiview (both eyes in one pass), and a governor that trims effects when frames run late.

Networking

Two players, one world

Host-authoritative world, client-authoritative movement. WebRTC carries game data and proximity voice; a Cloudflare Durable Object per room does signalling, with matchmaking and TURN on the same Worker.

Input

One bow everywhere

Input is raw poses (head and both hands) from WebXR, desktop or a bot, so the draw-and-release bow behaves the same for a player, a test and a balance sweep.

Testing

An emulated headset in the tests

488 Vitest tests, seeded bot runs for balance reports, and an end-to-end test that emulates a Quest 3 (IWER), enters VR and drives the controllers through real XR frames.

Shipping

A website and a store app

One codebase serves the browser and the store app: a Trusted Web Activity with a service worker for offline play, entitlement checks for the Full Game unlock, and separate debug and release builds.

attractor.fashion

A print-on-demand shop concept for strange-attractor art: chaos maths turned into posters, tees and hoodies.

WordPressWooCommercePrintify APICustom child themeGenerative artPrint on demand

Honest status: the shop is a working storefront in demo mode, more a concept than a live business. It takes no orders yet.

Visit attractor.fashion ↗
The collection

2,360 designs on one page

Generated from five families of equations, each attractor with its own name and palette. The whole index ships as compact JSON, so search by name or number, family filters and sorting by number or colour run in the browser.

Curation

Only what survives fabric

65 chosen designs are products, each on a shirt colour it shows on, with a print file made for that garment. Any of the 2,360 can be ordered as a poster.

Demand first

Notify me, then print

Designs not in the shop take an email signup instead of a cart; the ones people ask for get printed first.

Fulfilment

Print on demand

WooCommerce with a custom child theme in front, Printify behind it: nothing in stock, each piece printed after the order by a partner close to the customer.

Print test

Smooth beat dithering

Smooth 300 dpi prints, blue-noise and halftone dots were tested on real shirts. Smooth kept the faintest strands, so that is what the shop prints.

Images

Rendered ahead of time

Every attractor is pre-rendered to WebP at several sizes for fast browsing; the chosen ones are also rendered at full print size so the faintest strands make it onto the cotton.
